# 跨 session 來源召回：本機可追溯基線

Author: Nio (Master) · Execution: Codex · Date: 2026-10-08

## 研究背景

既有協作方式已保存對話及摘要，也有模型審查紀錄。但下一次 session 仍需找對來源，辨識哪些是使用者原話、哪些是摘要或歷史推測。這次把「找回與驗證」抽成可獨立重跑的工具。

## 研究目標

測試來源召回、原文行號／指紋一致性，以及來源修改後是否拒絕舊引用。目標不包含證明摘要保真、決策自動判讀或跨模型記憶能力提升。

## 既有方法探討

沿用 raw／structured 分層與重要論述回查 raw 的設計。既有 NotebookLM 發布 log 是發布紀錄，不能證明今天的雲端資料仍存在，也不能作為召回品質結果。原始技能的 reviewer `pass` 是當次流程結論；未綁版本的舊 verdict 不能替現有檔案背書。

## 材料與方法

- 本機 context_log 29 組檔案，唯讀匯入；原文、私人檔名清單及索引留本機 ignored `runs/`。
- 另製 3 份合成文件，含「凍結／否決」「預算／成交價」「測試／正式環境」差異。這是開發者設計的測試資料，不是獨立測試集。
- 對歷史資料先保存 5 題查詢及各自預期檔案，再搜尋 top 5；另加 1 題不存在的識別字。出題者已讀過部分資料，因此非盲測。
- 每個回傳片段核對完整檔案 SHA-256、行號、文字、來源 metadata 與 raw 配對。
- 實作測試用暫存資料夾，結束自動清除；真實實驗證據留本機以供追溯。

## 結果

| 項目 | 本次觀察 |
|---|---|
| raw／structured | 各 29 份，29 組配對，無孤立檔案 |
| 索引 | 58 份文件，557 個行視窗 |
| 歷史 metrics | 27 筆，20 pass、7 unresolved；2 組沒有 metrics |
| 指定來源進前五名 | 3／5 題 |
| 不存在識別字 | 0 命中 |
| 引用一致性 | 25／25 回傳片段通過機械驗證 |
| 程式回歸測試 | 25 項通過 |

**引用一致性與召回品質是兩個不同結果。** 即使回傳內容逐字正確，也可能不是問題需要的來源。

五題診斷依序涉及儲存架構、凍結語意、邏輯 vault 整合、handoff、迭代上限。前三題預期來源命中；後兩題未命中。

後查 handoff 題發現開發者把預期文件標成 part 1，實際相關討論在 part 2，而搜尋確實返回 part 2。這是**測試標註錯誤**，不是已確認的檢索失敗；保留原始 3／5，不事後換標準宣稱提升。迭代題使用跨多篇都有的通用詞，前五名被其他文件占滿，仍需更精確的意圖與人工判準。

另發現一份 `unresolved` 歷史紀錄對應的摘要帶有後續人工解決註記。因此上述 7 筆是**自動流程歷史 verdict**，不能寫成「目前仍有 7 筆未解決」。最終匯入器把 frontmatter 與 metrics 的不同值列為衝突，該筆標 unknown，沒有代替使用者裁決。修正後索引 metadata 為 20 pass／6 unresolved／3 unknown，其中 1 筆是狀態衝突。

## Reviewer 與修正

獨立 reviewer 在 16 項原測試通過後，實際重現兩項缺陷：索引輸出能覆寫無關檔案；引用驗證兩次讀檔之間若內容改變，可能錯配文字與 hash。修正為既有輸出拒絕覆蓋、原子排他發布、單一 byte snapshot 驗證；增加對應回歸測試。第二輪 review 另抓出正文中 status 字串會被誤判為 metadata；已改為只讀 frontmatter 並明列衝突，補上測試。

## 討論

本版可展示來源契約、版本核對、失敗處理、唯讀匯入及可重跑測試。它將既有協作方法變成可檢查的工程介面。技術價值在於明確限制「可以證明什麼」，並讓錯誤可重現和修正。

小樣本、開發者出題、一次錯標與模型 reviewer 都限制結論。沒有人工 gold set、比較組、模型答案評分或效能測試，不能說優於 NotebookLM、RAG 或全文搜尋。本機詞彙方法也不理解同義詞與決策時效。

## 結論

完成可下載重跑的來源召回基線，引用一致性與檔案失效檢查已驗證。下一步應先建立獨立查詢與標註，分開衡量檢索、引用、語意支持及決策時效，再選擇是否加入混合檢索與生成層。
